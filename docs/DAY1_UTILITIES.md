# Day-1 Utility Engine

Implements [work order #002 / Issue #3](https://github.com/avantic-labs/avantictools/issues/3).
`AGENTS.md` and `DAY1_ARCHITECTURE.md` remain authoritative. This document records
utility behavior and verification; it does not introduce product/design decisions.

## Boundaries

- The five canonical `/tools/…` URLs are statically generated by a Server Component
  shell using names, descriptions and URLs from `data/day1-tools.ts`.
- Only the interactive controls are Client Components. Input and output live in
  component memory. No API/server action, database, browser storage or provider
  credentials are involved. Leaving/reloading a tool resets its application state.
- No new AI, authentication, Detector, Humanizer, Audit, AVA or Phase-2 behavior.
- Existing neutral CSS variables control the new controls. No new brand palette,
  typography system or external fonts were introduced.
- All navigation in utility shells disables prefetching, keeping tool interaction
  independent of background route requests.

## Defined behavior

### Word Counter and Character Counter

Both use `countText` in `lib/utilities/text.ts`. Counts update while editing/pasting.
Characters are Unicode grapheme clusters, including spaces and line breaks.
Combining accents, emoji modifiers and joined emoji remain one character. CRLF is
one grapheme; textarea line endings are normalized by the browser. Words use
English-locale `Intl.Segmenter` word-like segments: numbers and contractions count;
punctuation and emoji alone do not. Hyphenated parts count separately. Scripts
without spaces use the browser's Unicode segmentation. Empty/whitespace-only text
has zero words. The rule is shown in both interfaces.

### Case Converter

Lowercase, UPPERCASE, Title Case and Sentence case share `convertCase`. English-locale
Unicode mappings preserve spacing and punctuation, and can expand characters
(for example, ß → SS). Title Case capitalizes each word without editorial small-word
exceptions. Sentence case starts at the first letter and after `.`, `!`, `?`, or a
line break. It does not infer abbreviations or proper names. The original stays
editable alongside a selectable read-only output. Clipboard success/failure is
announced without including text in the announcement.

### QR Code Generator

The MIT-licensed `qrcode` package runs in the client bundle. It encodes the original
input as UTF-8 bytes, with medium error correction and a four-module quiet zone.
The documented limit is 2,331 UTF-8 bytes (version 40, level M); blank and oversized
input get accessible validation. Surrounding whitespace is preserved for nonblank
input. A local canvas produces a PNG data URL; the preview bypasses Next image
optimization and downloading uses a temporary browser anchor. Nothing is uploaded.
Editing invalidates the old result and stale asynchronous generation cannot replace
the current result. Shorter content is recommended for easier scanning.

### Password Generator

Passwords are generated only after a browser action, never during server rendering.
Length is a whole number from 4 to 128, with 20 as the default; the interface
recommends at least 16. Lowercase, uppercase, numbers and ASCII symbols are supported.
The last selected class cannot be deselected. Invalid lengths disable generation;
the shared logic separately validates options. Changing options clears the result.

Web Crypto `crypto.getRandomValues` is the sole random source. Byte rejection
sampling removes modulo bias; whole candidates missing a selected class are rejected.
Every allowed selection is satisfiable, and every valid string is equally likely.
Unavailable/failing Web Crypto gives a generic error with no weak fallback.
Generated values, options and raw errors never enter analytics, logs or storage.
Copying is an explicit user action; clearing does not change the device clipboard.

## Analytics boundary

The foundation supplies an `AnalyticsClient` interface but no configured provider.
This work adds a browser-local `avantic:analytics` event bridge using that canonical
event shape. It emits only `tool_viewed` and `tool_completed`, an allowlisted `tool_id`,
and an allowlisted action (`count`, `convert`, `generate`, `copy`, `download`). It
accepts no arbitrary property bag. Runtime validation also rejects unknown values.
Counting/conversion completion is emitted once per visit; explicit generation,
copy and download emit on success. No input, counts, URLs, options, clipboard data,
passwords, user identifiers or raw exceptions are collected. No analytics request is made.

A future approved PostHog adapter can subscribe to this bridge. It must preserve
this boundary, disable autocapture/session replay on utility surfaces, and avoid
automatically enriching events with user content. Provider wiring is outside this
work order and requires no secrets here.

## Verification evidence — 2026-10-17

- `npm run lint`: passed with zero errors/warnings.
- `npm run typecheck`: passed (`next typegen` and `tsc --noEmit`).
- `npm test`: 61 tests passed across four unit suites.
- `npm run build`: passed with all five utility paths statically generated.
- `npm run test:e2e`: 28 tests passed against that production build, using desktop
  Chromium at 1280×720 and mobile Chromium at 412×839.
- All five populated tools passed axe checks for WCAG 2 A/AA, 2.1 A/AA and 2.2 AA
  with no reported violations or horizontal overflow at those sizes.
- Actual downloaded PNGs decoded to the exact synthetic Unicode payload. Password
  tests verified class coverage, minimum/maximum lengths and Web Crypto use without
  printing generated passwords.
- Operation-time browser observation found zero requests, WebSockets, console
  events or storage writes across all five tools, including generation, copying
  and downloading. Local analytics properties were checked against the allowlist.

Final source review covered accessibility, security/privacy, shared logic,
maintainability and scope. Review repairs included an accessible brand name,
clipboard cleanup after unmount and disabling catalog prefetch for foundation
routes. No utility server/API route, persistence, arbitrary analytics property bag,
new product surface, credentials or brand tokens were added. Exact commit,
Vercel Preview IDs/URLs and deployment readiness are recorded in the review PR.

## Reproduce verification

Use Node.js 24 (matching the existing Vercel projects):

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

The browser suite starts the production build, runs desktop and mobile Chromium
projects, and checks functional flows, keyboard access, overflow, axe accessibility,
clipboard success/failure, PNG roundtrip decoding and operation-time privacy.
Unit tests cover shared Unicode/case behavior, every password-class combination,
cryptographic rejection/validation, QR byte limits/decoding and the analytics
allowlist. Browser traces, screenshots and videos are disabled to keep entered
content and generated passwords out of test artifacts.
